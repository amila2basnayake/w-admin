Read this carefully

Upside is measured against the later median with the benefit of hindsight — it is not a claim the client mis-timed the sale, and it ignores their liquidity needs at the time. Use it to start a conversation, not to grade a decision.

The query behind this list

Read-only · runs with your access scope · shown for auditability
copy-- settled sells vs later median for the same region + product, your book only SELECT ru.display_name, oc.region_id, oc.quantity_ml, wo.price_per_ml AS sale_px, m.median_since AS median_px, (m.median_since - wo.price_per_ml) AS gap FROM order_completed oc JOIN wateroffer wo ON wo.id = oc.wateroffer_id JOIN registry_user ru ON ru.id = oc.registry_user_id JOIN LATERAL median_after(oc.region_id, oc.product, oc.completed_at) m ON true WHERE oc.side = 'SELL' AND oc.completed_at >= '2025-07-01' -- this season AND (m.median_since - wo.price_per_ml) > 0 -- sold below later median AND EXISTS (SELECT 1 FROM tenant_to_user tu -- ← the tenancy gate, always WHERE tu.registry_user_id = ru.id AND tu.tenant_id = :tenant AND tu.broker_id = :me) ORDER BY gap * oc.quantity_ml DESC;
The EXISTS (… tenant_to_user …) clause is mandatory — the DB has no row-level isolation, so dropping it would leak every client. Prices come from wateroffer on settled trades, never the stale region indicative.

Assumptions

  • "Median since" = median settled price for the same region & product, from the client's sale date to today.
  • Upside is pre-fee and hindsight-based — it excludes the client's liquidity needs at the time of sale.
  • The stale ~2022 region indicative price ($60) is excluded; pricing is settled-trade only.
  • Only opt-in clients are listed — consent flags applied before the list was built.
